# 특허명세서 워크벤치

준비단계, 명세서 작성, 검증·수정 모듈을 모듈 계약 `1.0`으로 연결한 로컬 웹앱 프로토타입입니다. Module 1은 프로젝트·청구항·기술자료·작성 조건을 브라우저에 저장합니다. Module 2는 준비 패킷을 받아 AI 초안을 작성하고 DOCX 파일을 제공합니다. Module 3은 번호가 붙은 문단을 직접 편집하거나 AI 수정안을 검토한 뒤, 버전명이 붙은 DOCX로 저장합니다.

## 실행

### Windows 배치 실행 파일

압축을 푼 전체 폴더에서 `setup_dependencies.bat`을 처음 한 번 실행해 의존성을 설치한 뒤, `전체모듈_연결실행.bat`을 실행하면 공용 서버를 시작하고 세 모듈 화면을 각각 브라우저 탭으로 엽니다. 단일 모듈은 `모듈1_준비단계.bat`, `모듈2_명세서작성.bat`, `모듈3_검증수정.bat`으로 실행할 수 있습니다. 개별 실행 파일도 같은 폴더의 `launch_module.bat`과 프로젝트 소스 폴더가 필요합니다.

이 파일들은 Windows 배치 실행 파일(`.bat`)입니다. Python 3가 설치된 Windows에서 실행하며, 자체 포함된 네이티브 `.exe` 패키지는 아닙니다. 각 모듈 코드는 아래 소스 경로에 그대로 들어 있습니다.

### 수동 실행

Python 3와 `python-docx`가 필요합니다. 프로젝트 폴더에서 다음을 실행합니다.

```bash
python3 -m pip install -r requirements.txt
```

AI 작성까지 사용하려면 서버 프로세스 환경에 API 키를 설정합니다. 키를 코드나 웹페이지에 입력하지 않습니다.

```bash
export OPENAI_API_KEY="여기에-개인-API-키"
python3 run_server.py
```

Windows PowerShell:

```powershell
$env:OPENAI_API_KEY="여기에-개인-API-키"
python run_server.py
```

브라우저에서 `http://127.0.0.1:8000/`을 열어 사용합니다. 기본 모델은 `gpt-5-mini`이며, 서버에서 바꿀 수 있습니다.

```bash
export OPENAI_MODEL="사용할-모델-ID"
export OPENAI_MAX_OUTPUT_TOKENS="16000"
python3 run_server.py
```

키 없이 실행하면 준비 모듈과 기존 초안 확인은 가능하지만, AI 초안 생성은 실행되지 않습니다. DOCX 생성과 AI 연결 API는 `run_server.py`가 제공하므로 `python3 -m http.server`로 대신 실행하면 사용할 수 없습니다.

## Module 2 사용 흐름

1. Module 1에서 프로젝트, 청구항, 기술자료와 구성별 작성 조건을 입력합니다.
2. **AI 작성 지시**를 누르면 패킷을 브라우저 저장소에 기록하고 Module 2로 이동합니다.
3. 필요하면 **패킷 가져오기**에서 `*_준비자료_v1.json`을 선택합니다. 전달 패킷은 `packet_schema_version: "1.0"` 형식이어야 합니다.
4. 추가 지시를 입력하고 **명세서 초안 생성**을 누릅니다. 생성된 본문은 화면에서 직접 수정되고 브라우저에 자동 저장됩니다.
5. **DOCX 다운로드**를 눌러 초기 명세서를 Word 파일로 저장합니다.

## Module 3 사용 흐름

1. Module 2에서 검수 JSON을 백업하거나 **검수 화면 열기**를 누릅니다. 같은 브라우저라면 저장된 초안이 자동으로 연결됩니다.
2. 우측 문서의 문단 번호를 눌러 수정 대상을 고르거나 좌측 번호 입력란에 `2, 5, 8`처럼 입력합니다.
3. 수정 지시를 입력하고 **지정 문단 수정 제안 받기**를 누릅니다. AI 제안은 좌측에 따로 표시되며, 검토자가 **이 문단에 적용**을 눌러야 우측 본문에 반영됩니다.
4. 우측의 각 문단은 직접 편집할 수 있습니다. 변경사항은 브라우저에 자동 저장됩니다.
5. **수정본 저장**을 누르고 확인하면 새 DOCX를 `프로젝트명_명세서-v1.docx` 형식으로 다운로드합니다. 다음 저장은 `-v2`, `-v3`으로 올라가며, 기존 파일을 덮어쓰지 않습니다.

작성 결과는 `document_schema_version: "1.0"`, `module_versions`, 문단 번호 및 수정 이력을 브라우저에 기록합니다. 검수 JSON은 다른 브라우저나 기기에서 초안을 가져올 때 사용할 수 있습니다.

## 구현 내용과 경계

- Module 1에서 Module 2로 패킷을 저장하고 화면 전환
- JSON 패킷 파일 가져오기와 `packet_schema_version` 검증
- 서버가 마스터 프롬프트를 읽어 AI 응답 API로 전달
- 청구항, 출처별 자료, 구성 점검 및 사용자 작성 조건을 작성 입력에 포함
- 결과 본문 직접 편집, 브라우저 자동 저장, 텍스트 복사
- 수정 본문을 DOCX로 출력
- 문단 번호 기반 수정 지시, 구조화된 AI 수정 제안, 선택 적용
- 확인 대화상자 이후 `-vN` 파일명으로 별도 버전 저장
- 서버 환경변수로 API 키, 모델, 출력 토큰 설정
- API 키가 없거나 형식이 맞지 않을 때 오류 안내

AI 작성 시 청구항과 기술자료가 설정한 AI API 제공자에게 전송됩니다. Module 3의 문단 수정 요청은 문맥 보존을 위해 문서 전체 문단, 지정 번호와 수정 지시를 함께 전송하며, 응답은 지정 문단의 제안으로만 표시됩니다. 발명정보의 처리 및 보관은 해당 제공자 계정의 정책과 사용 설정을 확인해 주세요. 이 프로토타입에는 로그인, 다중 사용자 접근 제어, 서버측 프로젝트 저장, 파일 첨부 업로드, 외부 자료 자동검색이 포함되지 않습니다.

## 마스터 프롬프트 관리

개발자가 수정할 수 있는 한국어 원문은 `docs/특허명세서_마스터_프롬프트.md`와 DOCX 원본으로 보관합니다. Module 2의 API는 프롬프트 본문을 클라이언트로 반환하지 않습니다. 다만 이 로컬 개발 패키지를 받은 사람은 소스 파일을 열 수 있으므로, 코드 패키지 안의 문서를 암호문이나 기계어로 바꾸는 것만으로 원문을 비밀로 보호할 수는 없습니다. 실제 비공개 서비스에서는 원문을 배포 코드에서 분리하고 서버 비밀 저장소 및 접근 통제를 적용해야 합니다.

## 모듈 버전

| 모듈 | 버전 | 패킷/문서 연결 |
| --- | --- | --- |
| 준비단계 | 0.1.0 | `packet_schema_version: 1.0` |
| 명세서 작성 | 0.2.0 | 입력 패킷 1.0, 문서 스키마 1.0 |
| 검증·수정 | 0.3.0 | 문서 스키마 1.0, 문단 번호 및 버전 저장 |

다음 모듈 업데이트 때는 각 모듈 버전과 `packet_schema_version` 호환성을 확인하고, 기존 계약을 변경하면 스키마 버전을 올려야 합니다. Module 3의 버전 이력과 수정본은 현재 브라우저의 localStorage 및 사용자의 다운로드 폴더에 저장됩니다. 서버 계정, 다중 사용자 접근 제어, 서버측 버전 파일 저장 기능은 아직 포함되지 않았습니다.
